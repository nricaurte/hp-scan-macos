## Recovery

Same-handle hardware test: cancel after `sane_start`, then `sane_read` returned
`CANCELLED` with zero bytes. Immediate restart returned `DEVICE_BUSY (3)`.
After a 12-second frontend wait, the same handle completed a new scan to EOF.

This validates cancel-after-start and post-job busy recovery, not cancellation
inside blocked USB I/O. USB disconnection, physical transport timeout and
simultaneous-client contention remain separate hardware checks; deterministic
fault injection covers software timeout/busy/error paths.

## scan-type=5 capability extension and cancellation recovery

USB connectivity was restored for this phase. The previous v0.4 candidate first
passed all seven Flatbed cases again. The capability-driven candidate then passed
the same seven cases, with the same dimensions listed in the original table.
ImageIO fully decoded every candidate JPEG. Runtime dyld logs confirmed loading
the candidate HPAIO, HPMUD, HPIP and native plugin, not the installed originals.

ADF Gray 150 with default geometry scanned **four pages**, all 1275 × 1753,
then returned NO_DOCS at page five and terminated the batch with exit 0.
ImageIO fully decoded all four files. No fifth blank image was produced.
The feeder subsequently reported PaperInADF=false; a reload was requested for
Color 300/A4 multi-page PDF. The earlier four-page Color PDF result remains
historical and is not claimed as a final-candidate PDF regression.

An eight-second SIGALRM during Color 600 initially produced CANCELLED but immediate
restart failed with I/O error; a subsequent capability query returned SOAP Error
32. The scanner eventually settled without a power cycle. After changing the
transport to finish an in-flight request/response before cancellation, the same
signal test passed: CANCELLED with zero bytes, immediate DEVICE_BUSY, then a
successful same-handle Gray 150 scan to EOF after a 12-second frontend wait
(2,235,075 raster bytes; entire test about 56.2 seconds).

A separate real `scanimage` process received SIGINT eight seconds into Color 600.
It printed `received signal 2`, `trying to stop scanner`, and `Operation was canceled`,
exiting 2 at about 34.6 seconds. A new Gray 150 scan after 12 seconds succeeded,
and ImageIO decoded the 1275 × 1753 JPEG. This establishes signal cancellation
and subsequent recovery, **not** immediate physical stopping: the response is
drained under the original image deadline before CancelJob.

The final capability/cancellation source was rebuilt from freshly extracted
HPLIP in `build/compatibility/release-candidate/hplip-3.25.8`. All four patches
passed reverse dry-runs. All sanitizer, patched-USB, wrapper and compiled-backend

Flatbed-only, ADF-only, Gray-only/wider ADF/600 DPI, namespace-prefixed replies,
unsupported HPRAW-only devices, and rejected DTD/entity declarations. Every
ADF preset retains its ticket over subsequent pages in software regression.

HPLIP 3.25.8 supplied 105 unique scan-type=5 candidate identifiers. Only M127fn
was physically tested; the alternate fixtures are synthetic schema tests, not
proof of compatibility with those models. See [Compatibility](COMPATIBILITY.md).

Evidence is under `build/compatibility/`: `release-candidate-build.log`,
`final-regression.log`, `final-sha256.json`, `loaded-libraries.log`,
